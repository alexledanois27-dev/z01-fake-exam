# Variables, types et fonctions

## Objectif

Lire le contrat d’une fonction JavaScript et distinguer sa valeur de retour de son affichage.

## À savoir

- `const` empêche la réaffectation d’une variable, pas la mutation d’un objet. `let` convient à une valeur réaffectée.
- `===` compare sans conversion implicite ; `==` peut convertir les opérandes.
- Une fonction qui ne retourne rien produit `undefined`. Une fonction fléchée avec accolades a besoin d’un `return` explicite.
- Lire les cas vides, les types des arguments et le type de retour avant de choisir une boucle.

## Exemple isolé de syntaxe

```javascript
const scale = (value) => value * 3;
const describe = (value) => {
  return `valeur:${value}`;
};
let total = scale(4);
total += 1;
console.assert(total === 13);
console.assert(describe(2) === "valeur:2");
```

Cet exemple illustre une notion ; il ne constitue pas la solution complète d’un
exercice. Conserver la signature et les restrictions annoncées dans la consigne.

## Pièges fréquents

- Confondre `console.log` et `return`.
- Utiliser une affectation `=` dans une condition par erreur.
- Compter sur une conversion implicite pour les entrées invalides.

## Vérification rapide

- La signature porte le bon nom.
- Mon retour a le type demandé.
- Je teste les cas zéro, vide et absent quand ils sont prévus.

## À essayer seul

Créer une fonction de transformation simple et vérifier sa valeur avec une assertion, sans afficher dans la fonction.
