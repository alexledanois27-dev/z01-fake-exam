# Boucles, accumulateurs et nombres

## Objectif

Construire un calcul progressif avec un cas de base et une condition d’arrêt.

## À savoir

- Un accumulateur de somme démarre généralement à 0 ; un produit à 1. Le contrat reste prioritaire.
- Écrire les bornes avant la boucle : le dernier élément est-il inclus ?
- `%` calcule un reste ; la normalisation d’un modulo négatif peut demander `((n % m) + m) % m`.
- Les entiers Number ne sont garantis exacts que jusqu’à `Number.MAX_SAFE_INTEGER`. BigInt n’est utile que si le contrat l’autorise.

## Exemple isolé de syntaxe

```javascript
const values = [4, 7, 2];
let total = 0;
for (const value of values) {
  total += value * value;
}
console.assert(total === 69);
const wrapped = ((-1 % 5) + 5) % 5;
console.assert(wrapped === 4);
```

Cet exemple illustre une notion ; il ne constitue pas la solution complète d’un
exercice. Conserver la signature et les restrictions annoncées dans la consigne.

## Pièges fréquents

- Multiplier à partir de zéro.
- Réinitialiser l’accumulateur à chaque tour.
- Écrire une récursion sans cas de base ou dépasser la précision des nombres.

## Vérification rapide

- Je connais la valeur de départ et le résultat du cas vide.
- La boucle termine pour les entrées prévues.
- Je vérifie à la main trois tours.

## À essayer seul

Calculer la somme des carrés d’une petite liste avec une boucle, puis expliquer comment l’invariant évolue.
