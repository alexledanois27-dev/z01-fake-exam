# Proxy, accès indirect et immutabilité

## Objectif

Intercepter une opération ou empêcher une mutation en connaissant les limites de ces mécanismes.

## À savoir

- Un `Proxy` intercepte des opérations telles que get ou set sur une cible ; `Reflect` permet de déléguer le comportement normal.
- Une interception doit préserver les invariants de l’objet, notamment ses propriétés non configurables.
- `Object.freeze` est superficiel : les objets enfants restent mutables s’ils ne sont pas gelés séparément.
- Une lecture par une valeur ou une clé transformée demande une politique sur les collisions et les propriétés absentes.

## Exemple isolé de syntaxe

```javascript
const target = { count: 2 };
const view = new Proxy(target, {
  get(object, key, receiver) {
    return Reflect.get(object, key, receiver);
  }
});
console.assert(view.count === 2);
const config = Object.freeze({ enabled: true });
console.assert(Object.isFrozen(config));
```

Cet exemple illustre une notion ; il ne constitue pas la solution complète d’un
exercice. Conserver la signature et les restrictions annoncées dans la consigne.

## Pièges fréquents

- Rappeler le proxy depuis son propre piège et créer une récursion.
- Promettre une immutabilité profonde avec un seul freeze.
- Ignorer les clés Symbol ou les collisions quand le contrat les traite.

## Vérification rapide

- Les propriétés normales restent accessibles.
- Je définis le comportement d’une propriété manquante.
- Je teste les contraintes d’écriture sans supposer qu’elles lèvent toujours une erreur hors mode strict.

## À essayer seul

Écrire un proxy qui observe seulement une lecture, puis comparer un objet gelé à un objet contenant un enfant encore mutable.
