# Récursion, chemins et références circulaires

## Objectif

Décomposer un objet imbriqué et éviter les visites infinies.

## À savoir

- Définir un cas terminal : valeur primitive, absence ou fin de chemin.
- Une récursion doit avancer vers une sous-partie ou marquer un objet déjà vu.
- `WeakMap` peut associer un objet source à sa copie pour conserver les relations ; `WeakSet` suffit parfois à mémoriser des visites.
- Comparer, cloner, aplatir et geler sont des opérations différentes. Préciser le traitement des tableaux et cycles dans chaque consigne.

## Exemple isolé de syntaxe

```javascript
const visited = new WeakSet();
function inspect(value) {
  if (value === null || typeof value !== "object") return;
  if (visited.has(value)) return;
  visited.add(value);
  for (const child of Object.values(value)) inspect(child);
}
const sample = { label: "demo" };
sample.self = sample;
inspect(sample);
```

Cet exemple illustre une notion ; il ne constitue pas la solution complète d’un
exercice. Conserver la signature et les restrictions annoncées dans la consigne.

## Pièges fréquents

- Utiliser JSON.stringify comme remplacement universel d’une copie profonde.
- Oublier de conserver les références partagées si le contrat les exige.
- Confondre valeur primitive, tableau et objet.

## Vérification rapide

- Je peux écrire le cas de base.
- Je teste un objet imbriqué et un cycle si autorisé.
- Chaque visite traite un objet au plus selon la politique choisie.

## À essayer seul

Dessiner un objet avec deux références vers le même enfant et une référence vers lui-même. Choisir ce que doit conserver chaque opération.
