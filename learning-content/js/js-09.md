# Timers, échéances et nouvelles tentatives

## Objectif

Construire une politique temporelle sans mélanger délai par tâche et délai global.

## À savoir

- `setTimeout` programme un rappel ; il ne garantit pas une exécution exactement à l’instant demandé.
- `clearTimeout` annule un timer encore actif. Nettoyer les timers après réussite ou échec.
- Une échéance globale se calcule depuis un instant de départ et ne se réinitialise pas à chaque exercice.
- Définir si count signifie nombre total d’essais ou nombre de relances. Une relance ne doit se produire que dans les cas demandés.

## Exemple isolé de syntaxe

```javascript
async function demo() {
  let timer;
  try {
    const timeout = new Promise((_, reject) => {
      timer = setTimeout(() => reject(new Error("délai")), 500);
    });
    const result = await Promise.race([Promise.resolve("prêt"), timeout]);
    console.assert(result === "prêt");
  } finally { clearTimeout(timer); }
}
demo().catch(console.error);
```

Cet exemple illustre une notion ; il ne constitue pas la solution complète d’un
exercice. Conserver la signature et les restrictions annoncées dans la consigne.

## Pièges fréquents

- Laisser des timers inutiles prolonger le processus.
- Relancer aussi les succès.
- Réinitialiser le budget temporel à chaque étape ou lancer plusieurs essais au lieu d’une séquence.

## Vérification rapide

- Je peux décrire la limite temporelle totale.
- Je compte précisément les appels au callback.
- Je teste count minimal et rejet immédiat.

## À essayer seul

Chronométrer trois tâches courtes sous une même échéance, puis expliquer la différence avec trois délais indépendants.
