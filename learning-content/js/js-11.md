# Grilles, directions et backtracking

## Objectif

Chercher dans une grille sans sortir des bornes ni réutiliser illégalement une cellule.

## À savoir

- Représenter une position par ligne et colonne ; vérifier la longueur réelle de la ligne.
- Une liste de directions évite de recopier une recherche pour chaque orientation.
- Une recherche en profondeur doit avoir un cas de succès et un cas d’arrêt.
- En backtracking, marquer une visite pour le chemin courant puis l’annuler lors du retour si les autres chemins peuvent réutiliser la cellule.

## Exemple isolé de syntaxe

```javascript
const grid = [["a", "b"], ["c", "d"]];
const directions = [[1, 0], [-1, 0], [0, 1], [0, -1]];
const inside = (r, c) => r >= 0 && r < grid.length && c >= 0 && c < grid[r].length;
const neighbours = directions.map(([dr, dc]) => [0 + dr, 0 + dc])
  .filter(([r, c]) => inside(r, c));
console.assert(neighbours.length === 2);
```

Cet exemple illustre une notion ; il ne constitue pas la solution complète d’un
exercice. Conserver la signature et les restrictions annoncées dans la consigne.

## Pièges fréquents

- Mélanger grille carrée et grille rectangulaire.
- Garder un marquage d’un chemin échoué pour tous les chemins suivants.
- Autoriser des diagonales ou une réutilisation de case non prévues.

## Vérification rapide

- Je connais les directions autorisées.
- Je teste un coin et une grille vide.
- Les visites correspondent au chemin ou au parcours global selon le problème.

## À essayer seul

Dessiner deux chemins qui partagent une cellule et décider à quel moment la marque de visite doit être retirée.
