# Objets, références et parcours de propriétés

## Objectif

Accéder aux propriétés en tenant compte des références, des tableaux et des valeurs absentes.

## À savoir

- Deux objets distincts ne sont pas égaux par `===`, même si leurs champs se ressemblent.
- `Object.entries` parcourt les propriétés propres, énumérables et à clé chaîne.
- `null` a `typeof "object"` : le tester avant une récursion sur un objet. `Array.isArray` distingue les tableaux.
- Une propriété absente et une propriété présente avec valeur undefined ne sont pas toujours équivalentes.

## Exemple isolé de syntaxe

```javascript
const item = { count: 2, nested: { ready: true } };
const shallow = { ...item };
shallow.nested.ready = false;
console.assert(item.nested.ready === false);
console.assert(Object.prototype.hasOwnProperty.call(item, "count"));
for (const [key, value] of Object.entries({ x: 3 })) {
  console.assert(key === "x" && value === 3);
}
```

Cet exemple illustre une notion ; il ne constitue pas la solution complète d’un
exercice. Conserver la signature et les restrictions annoncées dans la consigne.

## Pièges fréquents

- Comparer des objets par identité alors qu’il faut comparer leur structure.
- Parcourir des propriétés héritées sans le vouloir.
- Confondre absence de propriété, null et undefined.

## Vérification rapide

- Je distingue copie et partage.
- Je traite null et les tableaux explicitement.
- Je sais quelles propriétés sont parcourues.

## À essayer seul

Créer deux objets avec le même contenu et comparer identité et propriétés, puis ajouter une propriété explicitement undefined.
